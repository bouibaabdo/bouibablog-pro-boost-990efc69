## المشاكل من PageSpeed Insights

1. **الشعار ضخم جداً** — `bouiba-logo.png` بحجم 1.8MB وأبعاد 1920×1920 بينما يُعرض بحجم 48×48 أو 84×84 فقط. توفير متوقع: **~1.8MB**.
2. **CSS يحجب العرض** (`styles-*.css` = 19KB, 790ms) — يؤخر LCP و FCP بـ 750ms.

## الحلول

### 1. توليد شعار محسّن وصغير (الأولوية القصوى)
- إنشاء نسخة PNG جديدة بحجم 192×192 بخلفية شفافة (يخدم @2x على شاشات retina لعرض 48-96px).
- رفعها عبر `lovable-assets create` واستبدال pointer الحالي.
- تحديث `<img>` في `site-header.tsx` و `site-footer.tsx` لإضافة `loading="eager"` + `decoding="async"` + `fetchpriority="high"` للـ header (LCP candidate).
- **توفير: 1815 KiB → ~15 KiB.**

### 2. تحسين استهلاك الشعار في الكود
- التأكد من أن `width`/`height` = 48 (كما هو موجود بالفعل ✓).
- إضافة `fetchpriority="high"` لشعار header فقط.

### 3. CSS blocking (تحسين ثانوي)
- CSS الحالي 19KB وهو معقول. TanStack Start يدمج CSS تلقائياً عبر Vite. الحل الوحيد الفعال هنا هو:
  - إضافة `<link rel="preload" as="style">` للـ CSS الرئيسي في `__root.tsx` head لتسريع اكتشافه (لكن Vite يفعل هذا تلقائياً في الإنتاج).
  - في الواقع، بعد إصلاح مشكلة الشعار (1.8MB أصغر) سيتحسن LCP بشكل جذري وتقل أهمية هذه النقطة.
- **قرار:** نتجاهل CSS blocking في هذه الجولة لأن التحسين الرئيسي (~1.8MB) من الشعار وحده سيقفز بنقاط PageSpeed.

## الملفات المتغيرة
- `src/assets/bouiba-logo.png.asset.json` (يُعاد إنشاؤه بأصل 192×192).
- `src/components/site-header.tsx` — إضافة `fetchpriority="high"`.
- (لا تغيير في `site-footer.tsx` غير الشعار الجديد الذي يُستخدم تلقائياً.)

## ملاحظة
الشعار الأصلي الحالي 1920×1920 مبالغ فيه لأيقونة تُعرض بـ 48px. توليد نسخة 192×192 يعطي جودة ممتازة على جميع الشاشات مع تقليل الحجم بنسبة **99%**.
